    員工活動點數集中管理平台

    員工參加公司活動即可累積點數，並用點數兌換禮品。活動管理員以 QR Code 或員工證感應發放點數，禮品管理員負責禮品目錄與發放，系統管理員確保每一筆帳都正確。本頁說明目前已完成的內容、畫面設計、各角色可以做的事，以及尚待決定的事項。

    • 網頁應用程式，支援手機與電腦，提供英文、日文、繁體中文
    • 登入使用公司 Microsoft 帳號（Entra ID）
    • 報到方式：QR Code 或連結、員工證（NFC／MIFARE）感應、人工輸入
    • 節慶主題依台灣節慶行事曆自動切換
    • 電子郵件通知透過公司 SMTP 伺服器寄送，範本可自行編輯
    • API 以金鑰提供其他系統串接（人資系統、員工餐廳機台、問卷工具）
    • 部署環境：公司內部 IIS、.NET 10、SQL Server

    畫面設計

    選定的設計方向是 Arcade：讓累積點數帶有一點遊戲感。點數餘額以等級圓環呈現，會隨著接近下一份好禮逐漸填滿；活動與禮品是像徽章一樣的卡片；報到成功或兌換禮品時會有小小的慶祝動畫。管理介面延續同樣的風格，但較為沉穩——它們首先是工作用的工具。

    標準配色

    平日使用公司的藍色與綠色。藍色為主色，綠色用於成功、進度與獎勵。下列色碼取自公開的商標圖檔，應以品牌規範的正式色碼取代（見待決事項品牌色）。

    藍#199ECF
    綠#75B42B
    灰#54555A

    節慶主題

    節慶期間網站會自動更換配色與裝飾。每個節慶都有專屬的像素風圖案與輕量的背景動畫。日期由系統逐年計算，農曆節日也包含在內，不需要有人維護時程表。系統管理員可以隨時略過某個節慶，或強制指定主題。

    節慶日期主題顯示期間下一次（系統計算）

    設計原則

    • 動畫流暢且有目的。數字會跳動累加、清單會滑動、頁面依序進場。裝置若設定「減少動態效果」，則改為簡短的淡入淡出。
    • 全站三種語言，包含管理員輸入的活動與禮品名稱（未填寫時以英文顯示）。
    • 員工介面以手機優先，管理介面以寬螢幕為主；支援淺色與深色。
    • 清楚易讀。每個主題的文字對比皆符合 WCAG AA，所有功能都能用鍵盤操作。

    各角色可以做什麼

    所有登入的人都是一般員工。系統管理員可以另外授予角色，一個人可以同時擁有多個角色。

    功能一般員工活動管理員禮品管理員系統管理員

    活動管理員只能看到自己負責的活動。另有唯讀的稽核角色（點數帳本、員工、稽核紀錄）——見待決事項稽核角色。

    員工可以做什麼

    查看自己的點數

    點數餘額、距離下一份好禮的進度、累計獲得與使用，以及每一筆異動與原因。報到中的活動會顯示自己是否已報到、是否已通過審核。

    活動報到

    用手機相機掃描活動的 QR Code（或開啟連結），必要時先登入，再按一個按鈕即可。活動若需審核，頁面會等待，並在活動管理員核准時顯示慶祝畫面。已登記員工證的人，在會場的讀卡機感應一下就完成。

    兌換禮品

    瀏覽附有圖片、所需點數與剩餘數量的禮品目錄。兌換時立即扣點並保留該項禮品；禮品發放後員工會收到電子郵件。每一筆申請都能在我的兌換中追蹤。

    活動管理員可以做什麼

    建立活動並設定點數

    以三種語言填寫名稱與說明，設定時間、地點、每次出席的點數與人數上限（選填）。每個活動可以選擇報到的審核方式（逐筆人工審核、名單內自動核准、全部自動核准），以及使用哪一種 QR Code。

    用 QR Code 發放點數

    固定連結：每個活動一個連結，適合印在海報上，搭配人工審核使用。動態報到碼：會場螢幕上的 QR Code 每 30 秒更換一次，轉傳給同事的照片很快就失效。另有適合投影機的全螢幕模式。

    審核報到

    待審核清單會即時更新。可以逐筆核准或退回、全部核准，或只核准名單內的人。現場報名的人會特別標示。

    刷卡站

    在入口放一台接上讀卡機的筆電：每感應一次就顯示姓名並立即發放點數。支援以鍵盤輸入方式運作的 USB 讀卡機；ACR122U 等 PC/SC 讀卡機則透過一支小型輔助程式連接。忘記帶員工證的人，可以改為輸入員工編號。

    參加名單

    匯入人資或報名表單匯出的 CSV。每一列都會與員工主檔比對：符合、查無此人、已離職或重複。之後若有新進員工加入，按重新比對即可，不需要重新上傳。

    禮品管理員可以做什麼

    管理禮品目錄

    以三種語言填寫名稱與說明，設定所需點數、庫存、每人兌換上限（選填）與上下架。每項禮品可以有多張圖片：上傳的圖片都會自動縮放到同一個正方形框內，不必修圖，目錄看起來也整齊一致。庫存異動都會連同原因留下紀錄。

    發放禮品並標記已發放

    每一筆兌換申請都會列在清單中，包含申請人、禮品與時間。禮品交給員工後，禮品管理員將它標記為已發放；清單會顯示由誰、在何時標記，員工也會收到電子郵件通知。標記錯誤可以復原；申請也可以取消，點數與庫存都會退回。

    系統管理員可以做什麼

    查看並更正每一筆點數

    點數帳本會列出每一筆異動。任何紀錄都不會被修改或刪除：錯誤是以撤銷（新增一筆相反的紀錄並連結到原紀錄）或附上原因的調整來更正，因此歷史紀錄永遠對得上，也看得出是誰做了什麼。

    人員、角色與員工證

    搜尋員工、查看餘額、授予或移除角色，並以感應方式登記員工證。

    節慶主題

    主題預設依節慶行事曆切換。管理員可以查看接下來的節慶、略過個別節慶，或強制使用某個主題（例如公司週年慶），之後再切回行事曆。

    電子郵件

    查看 SMTP 伺服器是否連線正常、寄送測試信、開啟或關閉各項通知，並以 {{employeeName}} 這類變數編輯各語言的主旨與內文。寄送紀錄會顯示已寄出與失敗的信件。

    每張圖由上往下閱讀。實線箭頭是動作，虛線箭頭是回應的結果。

    系統架構

    • 點數是一本帳。每一筆發放、兌換、調整與撤銷都是一列永不更動的紀錄。餘額由這本帳推算而來，並能防止同時發生的重複操作（重複掃描、最後一份禮品被兌換兩次）。
    • 電子郵件不會遺失，也不會誤報。信件與它所通知的異動一起儲存，再由背景程式寄出；郵件伺服器故障時會自動重試。
    • 圖片一律重新編碼。上傳的圖片由伺服器解碼後重新產生（統一尺寸、移除位置等資訊），並以隨機檔名存成一般檔案。
    • 其他系統各自取得權限受限的金鑰（讀取點數、增減點數、同步員工資料）。金鑰只儲存雜湊值，並可隨時撤銷。
    • 員工證卡號是識別碼，不是機密：感應一次代表「這張卡曾在這裡」，可信度與在名單上打勾相同。
